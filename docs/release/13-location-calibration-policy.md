# 地点与时间校准策略

当前业务前端提供中国省市选择，但只保存名称。仓库没有全国授权坐标文件、地点表或可复用前端坐标；服务端只有 P1-B 前已经存在的 11 个城市坐标：北京、上海、广州、深圳、成都、重庆、杭州、武汉、西安、南京、兰州。

这些记录被移入 `app/locations.py`，使用内部稳定代码，数据版本为 `project-built-in-cities-v1`。未下载、推测或新增任何坐标。客户端经纬度只有与服务端记录在 0.01° 内一致时才被接受，不能成为权威来源。

| 状态 | 语义 | 前端行为 |
|---|---|---|
| `applied` | 精确命中服务端记录并完成校准 | 可显示校准后时间 |
| `not_required` | 用户声明出生时间未知 | 不显示校准后时间 |
| `unavailable` | 缺少地点 | 不显示，输入校验通常先拒绝 |
| `invalid_location` | 代码/坐标不匹配或非法 | 不显示校准时间 |
| `unsupported` | 地点不在版本化数据中 | 显示“未完成地点校准” |
| `legacy_unknown` | 历史记录无法证明校准方式 | 不声称已校准 |

校准当前为可选增强：不支持的地点继续用用户输入的当地钟表时间运行现有算法，但明确记录未校准；绝不再用 120° 伪装命中。只有 `applied` 能显示“校准后时间”。

**上线阻塞：** 11 个城市不足以覆盖前端全国选择范围。获得经授权、完整、版本化并含稳定行政区代码的地点数据，完成同名城市、时区和边界测试前，P1-B 保持 BLOCKED，生产不得开启 V2 或宣称全国校准。
